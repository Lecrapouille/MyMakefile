# 🎯 3. Targets

**What you will learn**

- the kinds of targets: applications, tests, libraries, objects, header-only;
- declare a target in the folder of its sources;
- what a target gives to the targets depending on it;
- the mistakes MyMakefile catches;
- the generated `project_info.hpp`, and sources generated by your own rules.

**Prerequisites**: [chapter 2](02-Getting-Started.md).

---

## 1. 🎯 A target and its variables

A **target** is a name added to `TARGETS`, plus variables prefixed by that name and a dot:

```makefile
TARGETS := mylib
mylib.TYPE := library
mylib.SOURCES := src/**/*.cpp
mylib.PUBLIC_INCLUDES := include
```

The name is the one of the file built (`libmylib.a`, `mylib.exe`...), unless `mylib.NAME` gives another one. It shall not start with `lib`: MyMakefile adds it to the libraries.

Its main variables, all optional:

| Variable | Meaning |
|----------|---------|
| `TYPE` | What to build (§2) |
| `SOURCES` | Files and patterns: `src/*.cpp`, `src/**/*.cpp` (recursive). C (`.c`), C++ (`.cpp`, `.cc`, `.cxx`) and assembly (`.s`, `.S`) |
| `INCLUDES`, `DEFINES` | Include folders and macros (without `-D`: `FOO BAR=1 DATA="/usr/share/foo/"`) of this target only. A string keeps its quotes |
| `PUBLIC_INCLUDES`, `PUBLIC_DEFINES` | The same, also given to the targets depending on it (§4) |
| `DEPENDS` | The targets this one uses (§4) |
| `PKG_CONFIG` | Packages of the system known to pkg-config: `glfw3 zlib` ([chapter 4](04-Third-Parties.md)) |
| `LIBS` | Libraries at the end of the link line: `-lpthread` |
| `CXXFLAGS`, `CFLAGS`, `ASFLAGS`, `LDFLAGS` | Flags of this target only |
| `WARNINGS` | `strict` (default), `paranoid`, `default` or `none` ([chapter 5](05-Compilation.md)) |
| `ARGS` | Arguments of `make run-<target>` and of `make check` |
| `WORKDIR` | The folder `make run-<target>` and `make check` run it in, relative to the target: `.` for a test that reads or writes files beside it. The root of the project by default |

The [reference](11-Reference.md) lists all of them. A variable MyMakefile does not know is a typo, and make says so:

```makefile
myapp.SOURCE := src/*.cpp     # !!! unknown variables myapp.SOURCE: a typo? Known: TYPE SOURCES ... !!!
```

## 2. 🧱 The types

| `TYPE` | Builds | Notes |
|--------|--------|-------|
| `executable` | `bin/<name>` | The default when the target has sources. `make run-<name>` runs it |
| `test` | `bin/<name>` | An executable built and run by `make check` only, not by `make` |
| `static` | `lib/lib<name>.a` | |
| `shared` | `lib/lib<name>.so.<version>` (`.dylib`, `.dll`) | With its links `.so.<major>` and `.so`. Built as static where shared libraries do not exist (Emscripten, MSVC) |
| `library` | both | |
| `objects` | the objects only | Linked as objects in the targets depending on it: no library, nothing removed by the linker |
| `header-only` | nothing | The default without sources: only gives its `PUBLIC_INCLUDES`, `PUBLIC_DEFINES`, `PKG_CONFIG`, `LIBS`. With `LIBRARIES`, libraries built elsewhere |
| `cmake` | what its own CMake builds | A third party ([chapter 4](04-Third-Parties.md)) |

A static library can hold the objects of other static libraries, targets or `.a` files, with `MERGE`: one library to install instead of several. A third party built by CMake, or given by `LIBRARIES`, gives its static libraries. The targets depending on the library then do not link them again.

```makefile
mylib.TYPE := static
mylib.MERGE := imgui implot external/libfoo.a
```

## 3. 📂 Declare a target next to its sources

The main `Makefile` lists, in `SUBMAKEFILES`, `.mk` files that declare more targets:

```makefile
SUBMAKEFILES := external/external.mk app/app.mk tests/tests.mk
```

In such a file, every path of a target (`SOURCES`, `INCLUDES`, `PUBLIC_INCLUDES`, `DATA`...) is relative to the folder of the file; in the main `Makefile`, to the root of the project. MyMakefile tracks the file it reads by itself: no `P := ../..` as in version 2.

The file adds its targets with `+=`, never `:=`, which would forget the targets declared before:

```makefile
# app/app.mk
TARGETS += myapp
myapp.SOURCES := src/**/*.cpp
myapp.DEPENDS := mylib imgui
```

While a file of `SUBMAKEFILES` is read, `HERE` holds its folder, for the flags that need a path:

```makefile
myapp.LDFLAGS := --preload-file $(abspath $(HERE)data)@data
```

Use `:=` with `HERE`, never `=`: its value changes from one file to the next. After the `include` of MyMakefile, the files can test `TARGET_OS` (`Linux`, `Darwin`, `Windows`, `Emscripten`), `HOST_OS` and `COMPILER_FAMILY` (`gcc`, `clang`, `msvc`): they are read after the toolchain is known.

```makefile
ifeq ($(TARGET_OS),Emscripten)
    myapp.LDFLAGS := -sUSE_GLFW=3
else
    myapp.PKG_CONFIG := glfw3 glew
endif
```

## 4. 🔗 Dependencies

`DEPENDS` names the targets a target uses. It then gets from each of them, and from what they depend on:

- their `PUBLIC_INCLUDES` and `PUBLIC_DEFINES`;
- their `PKG_CONFIG` packages and their `LIBS`;
- their libraries, or their objects for an `objects` target, on the link line.

The libraries are linked in the right order (a library before the ones it uses) whatever the order of the `DEPENDS`, and built before the target. A target depends on the `INCLUDES` and `DEFINES` of no other target: only the public ones travel.

A shared library a target links has its folder in the run time path of the target (rpath), so that `make run-<target>` finds it without `LD_LIBRARY_PATH`. `RPATH` adds folders: `myapp.RPATH := /opt/foo/lib:/opt/bar/lib`.

## 5. 🛑 The mistakes MyMakefile catches

Before compiling anything, make stops with a message on:

| Mistake | Example |
|---------|---------|
| a missing `PROJECT_NAME` or `PROJECT_VERSION` | |
| a dependency cycle | `a.DEPENDS := b` and `b.DEPENDS := a`: `dependency cycle: a b a` |
| an unknown target in `DEPENDS` | `myapp.DEPENDS := mylibb`: `'myapp' depends on 'mylibb' which is not in TARGETS` |
| a dependency on an executable | `myapp.DEPENDS := othertool` |
| a source file or a pattern matching nothing | `myapp.SOURCES := scr/*.cpp`: `myapp.SOURCES: no file for 'scr/*.cpp' in the root of the project` |
| a library without sources | `mylib.TYPE := static` and no `SOURCES` |
| a name starting with `lib` | `TARGETS := libfoo` |
| a pkg-config package not installed | `myapp needs the packages 'glfw3', unknown to pkg-config: install them or set PKG_CONFIG_PATH` |

and warns about a variable of a target it does not know (§1).

## 6. 📝 `project_info.hpp`

With `t.PROJECT_INFO := 1`, MyMakefile writes `$(GEN_DIR)/<name>/project_info.hpp`. `GEN_DIR` is `build/<configuration>/gen`, an include folder of the target and of the targets depending on it. The header is included with the same line from the build and once installed, since `make install` puts the one of a library in `$(INCLUDEDIR)/<name>/`:

```cpp
#include "myapp/project_info.hpp"

namespace info = generated::myapp;
std::string const search = info::paths::data;   // folders split on info::paths::separator
```

Its namespace `generated::<name>`, in lower case with `-` and `.` replaced by `_`, keeps apart the headers of an application and of its libraries. It holds, as `constexpr` values:

| Name | Value |
|------|-------|
| `name` | The name of the target |
| `application::name`, `summary`, `log` | Its name, its `DESCRIPTION`, the name of its log file |
| `version::full`, `major`, `minor`, `patch` | `PROJECT_VERSION` |
| `compilation::mode`, `name` | The compilation mode, to compare with `compilation::debug`, `release`... |
| `git::branch`, `sha1` | The commit the project was built from |
| `paths::separator`, `data`, `tmp`, `log` | The data folders (the `DATA` of the target, in the sources then once installed), the temporary and log folders |

and the same as macros, for C and the preprocessor: `MYAPP_VERSION_MAJOR`... A target `my-app` gets `generated::my_app` and `MY_APP_VERSION_MAJOR`.

The header is written again only when one of its values changes, so a new commit does not rebuild the whole project.

## 7. ⚙️ Generated sources

Sources made by a rule of the project, for example shaders embedded in C++, are declared with `GENERATED_SOURCES` and `GENERATED_HEADERS`, relative to `$(GEN_DIR)`. MyMakefile compiles the sources, makes the targets using the headers wait for them, and does not report them missing:

```makefile
app.GENERATED_SOURCES := shaders.cpp      # $(GEN_DIR)/shaders.cpp
app.GENERATED_HEADERS := shaders.hpp      # $(GEN_DIR)/shaders.hpp

include .makefile/MyMakefile.mk

$(GEN_DIR)/shaders.hpp $(GEN_DIR)/shaders.cpp &: $(wildcard shaders/*.glsl)
	./tools/embed-shaders $^ $(GEN_DIR)/shaders
```

The rule comes after the `include`, where `GEN_DIR` is known.

## 8. 🪝 Hooks

| Variable | Run |
|----------|-----|
| `PRE_BUILD` | Commands run before compiling anything |
| `POST_BUILD` | Commands run after `all` |
| `t.POST_BUILD` | Commands run after the target `t` is built |

`clean`, `distclean`, `veryclean`, `install` and `uninstall` are double-colon rules: the project adds its own recipe to them.

```makefile
clean::
	rm -f data/cache.bin
```

`t.CLEAN` lists files and patterns removed by `make veryclean`, `CLEAN_FILES` those of the project.
